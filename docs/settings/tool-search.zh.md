# 工具搜索（`toolSearch.*`）

聊天中启用的工具很多时，宿主无法把全部工具交给模型：Copilot 会截断工具列表（即 **The model only supports 128 tools** 提示），而且每个函数定义都会占用 input tokens。启用工具搜索后，扩展只发送与当前对话相关的工具，并额外提供一个搜索入口 `multi_model_tool_search`。模型需要其他工具时先搜索，读到参数定义后直接调用。

## 设置

| 设置 | 默认值 | 说明 |
|---|---|---|
| `toolSearch.mode` | `auto` | `auto`：已启用工具多于 `toolSearch.maxTools` 时裁剪列表；`off`：始终发送全部已启用工具 |
| `toolSearch.maxTools` | `24` | 单次请求保留的工具数量，搜索入口不占用该额度 |

## 行为

- 名称或描述与最近几条用户消息匹配的工具优先保留；剩余名额按宿主顺序补齐，让相邻轮次的工具列表尽量接近，保持提示词前缀可缓存。
- 同一对话中由 `multi_model_tool_search` 搜索出来的工具，会在后续轮次继续发送。
- 被宿主从提示中截断、但仍在 VS Code 中注册的工具，同样可以搜索到并调用。
- 同时开启 `experimental.stabilizeToolList` 时，命中工具搜索的请求会跳过预激活：把全部 `activate_*` 组展开只会再把工具列表撑大。

## 缓存稳定性

DeepSeek 的上下文缓存按请求前缀命中，而 `tools` 定义位于消息之前，列表一变整段缓存就失效。因此工具搜索只在对话的**第一轮**按相关性挑一次，之后每一轮都原样复用这份列表：

- 搜索入口固定在数组**第一位**，其余工具只会在**末尾追加**，因此追加已解锁工具时前缀仍然命中。
- 宿主不再提供的工具（例如被 `配置工具` 关掉）会被移除，这是唯一会改变列表中段的场景。
- 同一对话的列表按「模型 + 首条用户消息」记忆（内存中保留最近 32 个对话）。

用 `debugMode: metadata` 可以在日志里看到 `[tool-search] … sticky=true appended=0`，以及 cache trace 的 `toolsChanged=false`。

## 限制

- 宿主自己的工具上限（例如 **配置工具** 提到的 128 个）由 Copilot 控制，本扩展无法提高；但只要请求里的工具数量明显低于该上限，就不会有工具被丢弃。
- 即使宿主把搜索入口从工具列表里裁掉，只要扩展注册过它，它仍会被补进请求。要恢复“始终发送全部工具”，请把 `toolSearch.mode` 设为 `off`。
